1. Text Adventure Games — gry tekstowe

Co robisz: program prowadzi Cię przez historię, a Ty wybierasz opcje.

Przykłady:

- gra typu „ucieczka z pokoju”

- przygoda w lochach

- wybór drogi: 1. Idź do lasu / 2. Idź do zamku

- Hangman / Wisielec też może tutaj pasować.


Ćwiczysz głównie: if, while, input, zmienne, funkcje, listy/stringi.


---

2. Login Systems — systemy logowania

Tak — logowanie użytkownika.

Przykład:

Username: Jarek
Password: ******
→ Login successful

Program może mieć:

rejestrację użytkownika

login

hasło

sprawdzanie poprawności danych

komunikat o błędnym haśle

limit prób logowania

wylogowanie


Walidacja oznacza po prostu: sprawdzenie, czy dane spełniają wymagania.

Np.:

Podaj wiek: abc
→ Błąd: wiek musi być liczbą.

3. Unit Converters — konwertery

Tu chodzi o zamianę jednej wartości/jednostki na inną.

Np.:

10 km → 6.21 miles
25 °C → 77 °F
2 kg → 2000 g
90 minutes → 1.5 hours

Zmiana małych liter na duże litery to nie konwerter jednostek — to raczej Text Processing.

Możemy zrobić nawet jeden większy Unit Converter, który ma kilka kategorii.

4. Logic & Guessing Games — gry logiczne i zgadywanki

Tutaj chodzi o programy, w których użytkownik musi odgadnąć albo logicznie rozwiązać problem.

Przykłady:

5. Quiz Games — quizy

Dokładnie tak, jak powiedziałeś.

B. Munich

D. Frankfurt

wpisywane słowo

liczba


Interpretowanie dowolnych odpowiedzi przez AI to już zupełnie kolejny poziom i możemy kiedyś zrobić taki projekt.

23. Simple Simulations — proste symulacje

To jest chyba najbardziej niejasna nazwa.

Symulacja = program, który naśladuje jakiś proces, żeby zobaczyć, co się wydarzy.

Przykłady:

Rzut kostką 1000 razy → sprawdzasz, ile razy wypadło 1, 2, 3 itd.

Symulacja kolejki → ludzie przychodzą, czekają i są obsługiwani.

Symulacja bankomatu → wpłata, wypłata, saldo.

Symulacja ruchu → np. samochód porusza się przez kolejne kroki.

Symulacja epidemii byłaby już bardziej zaawansowana, ale również jest przykładem symulacji.


---

I najważniejsza rzecz

Te grupy nie są od siebie szczelnie oddzielone.

Jeden projekt może ćwiczyć 5–6 grup jednocześnie.

Przykładowo Login System może zawierać:

Login System → Data Validation
→ Error Handling
→ File Handling
→ Data Processing
→ Modules
→ String Processing

I właśnie dlatego nie musimy teraz tworzyć 100 osobnych projektów. Robimy konkretny program, a przy okazji uczymy się kilku rzeczy naraz.

To będzie dużo bardziej naturalny sposób nauki niż próba „odhaczania” każdej kategorii osobno.
